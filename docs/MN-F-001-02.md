# ใบแจ้งซ่อมและตรวจรับเครื่องจักร MN-F-001-02

ปรับวันที่ 27 ตุลาคม 2026 ตามไฟล์ `MN-F-001-02 ใบแจ้งซ่อมและตรวจรับเครื่องจักร.xlsx` ชีต `Sheet1` ช่วง `A1:I35` ที่ผู้ใช้ส่งมา

## การใช้งาน

1. เปิด `/tickets/create` เลือกประเภทเครื่องจักร กรอกหัวข้อ วัน/เวลาแจ้ง ชื่อหรือรหัสเครื่องจักร สถานที่ แผนก ความเร่งด่วน P1/P2/P3 ปัญหาที่พบ และวันที่/เวลาที่สามารถเข้าแก้ไข (ถ้ามี) ผู้แจ้งมาจากบัญชีที่เข้าสู่ระบบ
2. แนบรูป JPG, PNG หรือ WebP หนึ่งรูป ไม่เกิน 10 MB และ 40 ล้านพิกเซล มีตัวอย่างก่อนส่ง เมื่อบันทึกแล้วรูปแสดงในใบงาน การดูรูปใช้สิทธิ์เดียวกับใบงาน
3. Maintenance รับงานเครื่องจักรที่ยังไม่มอบหมาย หรือผู้จัดการมอบหมายตามระบบเดิม ผู้รับงานกรอกผู้รับแจ้ง/วันที่ ความเร่งด่วน แนวทางซ่อมภายใน/นอก ความผิดปกติ EE/ME/อื่น ๆ ผู้ดำเนินการ วัน/เวลาเริ่มและเสร็จ รายชื่อช่างสูงสุด 6 คน สาเหตุ วิธีแก้ไข วิธีป้องกันซ้ำ และอะไหล่สูงสุด 7 รายการ
4. บันทึกร่างไว้ก่อนได้ เมื่อซ่อมเสร็จต้องกรอกข้อมูลหลักครบ ระบบคำนวณเวลาที่ใช้จากวันเวลาเริ่มและเสร็จ รองรับข้ามวัน และแจ้งผู้แจ้งตรวจรับ
5. ผู้มีสิทธิ์ตรวจรับเลือกพร้อมใช้งานปกติแล้วยืนยันปิดเคส หรือเลือกชั่วคราว/แก้ไขอีกครั้งพร้อมข้อเสนอแนะแล้วส่งกลับ วันที่และผู้ตรวจรับถูกบันทึก โดยผู้ตรวจรับมาจากบัญชีจริง คงสิทธิ์ manager/Admin ปิดแทนตามระบบเดิม

## การจัดเก็บและความเข้ากันได้

- ใช้ `work_items`, `work_events`, `portal_notifications` เดิม เพิ่มตาราง `work_machine_forms` ในฐานข้อมูลเดิม แยกข้อมูลแจ้งซ่อม ผลซ่อม และตรวจรับเป็น JSON และบันทึกสำเนาผลซ่อม/ตรวจรับในประวัติทุกครั้ง ไม่แปลงความคิดเห็นเก่าเป็นผลซ่อม
- ติดตั้งด้วย `php database/install_machine_repair_forms.php`; การติดตั้ง Intranet ใหม่ผ่าน `database/migrate_intranet.php` รวมตารางนี้แล้ว
- ตรวจสิทธิ์และ version ภายใต้ transaction เดียวกับใบงาน ป้องกันบันทึกทับงานที่มีคนอื่นเปลี่ยนแล้ว รวมถึงการแจ้งเตือนและประวัติ
- ชื่อ/รหัสเครื่องจักรในแบบฟอร์มเป็นข้อความตามเอกสาร ไม่ใช่รายการอุปกรณ์ IT และยังไม่เชื่อม `machines.id` อัตโนมัติ
- P1/P2/P3 ของผู้แจ้งเก็บตรงแบบ และใช้ urgent/high/normal ในรายการงานตามลำดับ ความเร่งด่วนของผู้รับแจ้งเก็บแยกในส่วนผลซ่อม
- งาน IT/อาคาร/อื่น ๆ ใช้ฟอร์มทั่วไปและแนบรูปได้ คำขออนุมัติยังใช้ PDF ตามเดิม
- ใบงานเก่าที่ไม่มีข้อมูล MN-F-001-02 ยังใช้ขั้นตอนเดิม เอกสาร PDF ที่แนบไว้ก่อนหน้ายังดาวน์โหลดได้ ไม่แปลงหรือทิ้งไฟล์เดิม
- ลายชื่อในเอกสารเป็นข้อความ ส่วนบัญชีผู้บันทึก/ตรวจรับและเวลามาจากระบบ ไม่ใช่ลายเซ็นดิจิทัล
- งานนี้เป็นหน้าเว็บกรอกตามช่องใน Excel ไม่ได้เพิ่มการส่งออก Excel/PDF

## การตรวจสอบ

- `php tests/machine_repair_forms.php`: ช่องข้อมูล การตรวจรับ สิทธิ์ version การเก็บข้อมูลเมื่อผิดพลาด ประวัติ ใบงานเดิม และชนิดไฟล์รูป
- `php tests/repair_workflow_ui.php` และ `php tests/repair_notifications.php`: ขั้นตอนรับงาน ซ่อมเสร็จ แจ้งเตือน และยืนยันปิดเคส
- ใช้ข้อมูล SQLite แยกจากฐานข้อมูลจริงในการทดสอบ การติดตั้งตารางไม่สร้างใบแจ้งซ่อมหรือแจ้งเตือนทดสอบให้พนักงาน
